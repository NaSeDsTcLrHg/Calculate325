# 独立校验层

目标：随机窗口里那条式子**真的**等于 325，而不是生成器自己说它等于 325。

做法：把最终渲染出去的 LaTeX 重新解析成 AST，用与生成器无关的方法重新求值，再用两套互不相干的实现交叉验证。

## 为什么必须做

旧实现的 `ClosedForm` 是 `delegate { return target; }`，`Verify()` 调它一下就永远通过；**渲染出来的那串 LaTeX 本身**从没被独立算过，模板拼错一处自检照样是绿的。

## 两套实现

| 实现 | 位置 | 用途 |
| --- | --- | --- |
| C# 审计器 | `src/cs/FormulaAudit.cs` | 自带 LaTeX 子集解析器 → AST → 复算，带误差界传播 |
| Python 独立实现 | `tests/verify/numengine.py`、`latex_ast.py` | 解析器与数值引擎全部重写，与 C# 零共享代码 |

两者都不许读生成器的中间结果，只吃最终 LaTeX 字符串。

## 数值方法

- 积分：tanh-sinh（双指数）为主，Gauss–Legendre 交叉验证；无穷区间用 `x = a + t/(1−t)` 映射；
- 级数：部分和 64→4096 + Neville 外推，几何级数直接闭式；
- 极限：沿几何序列逼近，必要时取单侧；
- 行列式：`Fraction` 高斯消元（Python）/ Bareiss（C#），精确整数。

## 运行时闸门

生成 → 审计 → 不过就换种子重生成。用户只会看到两套实现都通过的那一条。

## 怎么跑

```powershell
.\tests\Calculate325-tests.exe --audit                          # 审计器自检 41 条
.\tests\Calculate325-tests.exe --audit-test out.txt 325 8 20261021   # 正向 40 + 负向 12
node tests\verify.test.cjs                                      # 两套实现交叉校验
```

## 这个校验层抓到的真 bug

- `80.8^{3}` —— 上标拼接错位，旧自检发现不了；
- 极限里常数因子被重复积分；
- 级数通项的哑变量被外层同名变量捕获；
- 行列式阶数变化时 `det` 与乘法次序不一致。

## 没有验证的东西

- 不用 CAS：这是"独立数值复算 + 误差界"，不是符号化简证明；
- 含 π、ln2 之类的式子靠两套实现交叉验证，不靠定理；
- 极端长式子偶尔会撞 6 秒预算，直接被闸门拦下（不会交付）。
