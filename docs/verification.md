# 独立校验层（可验证性设计）

> 目标：随机窗口里那条式子**真的**等于 325，而不是生成器自己说它等于 325。
> 做法：把最终渲染出去的 LaTeX 重新解析成 AST，用与生成器无关的方法重新求值，
> 再用两套互不相干的实现（C# 内置 + Python 外部）交叉验证。

---

## 0. 为什么必须做

旧实现的 `RandomExprResult.ClosedForm` 是：

```csharp
r.ClosedForm = delegate { return target; };   // 恒等于目标
```

`Verify()` 只是调它一下，所以永远通过。因子链的乘积、矩阵行列式虽然有校验，
但**渲染出来的那串 LaTeX 本身**从来没有被独立算过。只要模板拼接写错一处
（例如下面第 6 节抓到的 `80.8^{3}`），自检仍然是绿的。

---

## 1. 两套实现

| 实现 | 位置 | 输入 | 用途 |
| --- | --- | --- | --- |
| C# 审计器 | `src/cs/FormulaAudit.cs` | LaTeX 字符串 | 运行时闸门：不过就换种子重生成 |
| Python 校验器 | `tests/verify/{latex_ast,numengine,check_dump}.py` | EXE 导出的 JSONL | 离线交叉验证，与 C# 零共享代码 |

两套都**只吃 LaTeX**：不读 `Fac`、不读 `ClosedForm`、不读任何中间变量。
Python 那边是照着数学另写的一份（自己的分词/递归下降解析 + 自己的求积/求和/极限），
不是把 C# 翻成 Python。

---

## 2. C# 审计器的结构

```
LaTeX ──分词/递归下降──► AST ──求值（每节点带误差界）──► 值 ± 误差
                                                          │
                                     声称值 325 ◄─────────┘  比较
```

- **解析**：支持本生成器会输出的全部子集 —— `\frac`、`\sqrt`、上下标、
  `\left...\right`、`\int/\iint/\iiint/\oint`、`\sum/\prod`、`\lim`、
  `\det\begin{pmatrix}`、`\left\lfloor/\lceil/\{`、`\zeta/\mu/\varphi`、
  `\mathrm{mod}`、`!`（`!!` 按项目约定 = 两次阶乘）。
  积分体延伸到本层的微分 `d<变量>`；求和/极限体延伸到本层乘积的末尾。
  **遇到不认识的构造直接抛 `AuditException` 判失败**，不会猜一个值放行。
- **数值方法**
  - 定积分：tanh-sinh（双重指数），端点奇点稳；
  - 半无穷：先做有理映射 `u=(x−a)/(1+x−a)` 再 tanh-sinh；
  - 嵌套积分（三重）：映射后改用 32 点 Gauss–Legendre，节点数是各维之积，
    双重指数会被罚到爆，GL 指数收敛；
  - 级数/连乘：部分和 + 尾部识别（几何级数直接收敛，`n^{-p}` 用 1/N 外推）；
  - 极限：序列外推（1/N 或 h）+ 常量因子分离；
  - 行列式：整数精确、Bareiss 无除法消元（与生成器的余子式展开不同算法）；
  - `\varphi`/`\mu`：整数分解；`\mathrm{mod}`：`BigInteger.ModPow` 精确模幂。
- **误差界**：每个节点带 `(Complex 值, 绝对误差界)`，逐层传播。
  最终 `|算出 − 声称| ≤ max(4×误差界, 1e-9×|声称|)` 记 `tight`；
  只满足 `|差| ≤ 1e-6×|声称|` 记 `approx`；
  **误差界 > 1e-3×|声称| 或预算/超时用尽 → 判"未验证"（不算通过）**。
  这条很关键：否则一个算歪的式子会因为误差界很大而被放行。

## 3. 少数必须用定理的原子

以下五类在数值上无法稳定判定（条件收敛、慢收敛、等分布），用**解析恒等式**，
参数一律从式子里读出来，代码里注明依据：

| 原子 | 恒等式 | 为什么不能纯数值 |
| --- | --- | --- |
| Dirichlet | `∫₀^∞ sin(αx)/x dx = π/2` | 条件收敛，tanh-sinh 会稳定收敛到错值 |
| Frullani | `∫₀^∞ (cos αx − cos βx)/x dx = ln(β/α)` | 同上 |
| sinc² | `∫₀^∞ sin²(αx)/x² dx = πα/2` | x 很大处节点间距超过振荡周期 → 混叠（实测 1.6e-5 相对误差） |
| Euler 素数乘积 | `∏_p (1−p⁻²)⁻¹ = ζ(2)` | 素数乘积收敛极慢 |
| Möbius Dirichlet | `Σ μ(n)/n^s = 1/ζ(s)` | Mertens 函数不规则，1/N 外推只到 1e-7 |
| 等分布 Cesàro | `lim (c/N)Σ_{k≤N}{k√p} = c/2` | 误差 O(log N/N)，N=1e6 也只有 1e-5 |

这些都是**结构化匹配 + 参数回代**，不是硬编码常数：例如 `log(β/α)` 的 β、α
是从式子里的 `\cos(βx)`、`\cos(αx)` 反解出来的。

## 4. 运行时闸门

`RandomExpr.BuildLevelGated(level, target, rnd, seed, allowHard)`：

1. 用给定种子生成；
2. `FormulaAudit.Audit(latex, target)` 独立复算；
3. 不过就**换种子重生成**，最多 4 次；
4. 返回实际用到的种子（`Seed`）、原始种子（`RequestedSeed`）、重试次数（`AuditTries`）。

随机窗口的状态栏会显示 `独立校验 325.000000000 ✓`（`≈` 表示落在 1e-6 松界内）。

### 4.1 L5 v2 的验证链（2026-10-23）

L5 走 `src/cs/L5Pipeline.cs`，验证分三层：

1. **构造层（exact）**：每个模型用整数/有理数直接算出 325
   （组合数、等差和、平方和、星条、期望、`det+tr²`、梯形面积、交错平方和、
   φ-floor、进位展开）。融合层只做值保持包装：
   `∫_A^B core/(B−A)du=core`、`(core)^{det(M)=1}=core`、旧 =1 模块 ×1。
   这是“325 来自模型本身”的保证，不是事后筛选。
2. **候选层（audit，选中候选）**：只对仲裁选中的候选跑
   `FormulaAudit.Audit`；失败时按 ranked 顺序试下一个 exact 候选。
   未选中的候选在审计链里是 `audit_ok=false / audit_mode=skipped`，
   不是“已验证”。这样 200 种子从 K 次审计降到约 1 次（约 47 s）。
3. **批内层（Python）**：`--dump-random` 导出的 L5 记录带
   `natural_model/topology/l5_chain`，由 `tests/verify/check_dump.py` 用
   `latex_ast.py + numengine.py` 独立复算；200 条语料 200/200，
   L5 40/40、最大相对误差 1.10e-11、40/40 `tight`。

审计链 `L5AuditJson` 记录：seed、schema_version、全部派生子种子、
候选顺序/排序、每个候选的 T1–T6、`generation_path`、`dag`、`params`、`domain`、
`verification_log`、最终 fingerprint 和 `retry_used`。

**融合层的两个硬约束**：

- 所有因子必须套不可见 `{}`。`Σ`/`lim` 的 body 会一直吃到后面的因子；
  实测 `8ΣΣΣ1/3^{...}·(核心)` 会被算成 288.888…，不是 325。
- 嵌套积分壳的上下限 A/B 必须用 `X.Paren(...)` 包起来；
  否则 `\int_{5·Σ1/2^p·Σ1/2^q}^{...}` 这类上下限会被解析错。
  这两条都由 `L5Hybridize` 统一处理，不要在旧模板里手写。

**一个真实边界**：C# 的 `NDet` 对“全是整数常量”的矩阵走 Bareiss 精确路径，
但含负元素的矩阵字面量会先被解析成 `0−n`，不再被识别为 `NNum`，于是走
数值高斯消元。实测 `det[[2,-51,-50],[3,-77,-76],[-7,205,203]]` 得到
`24.999999999999538`；如果它直接进 `floor`，M9 会掉一档得到 300。
处理方式：M9 改用整数和构造 `D=25`；其余模型只把 det 用在阶乘/求和上限/
积分上限/幂指数上，这些位置对 ±1e-15 不敏感（或会先四舍五入）。
后续可在 `NDet` 里把 `NAdd(0, n, Sign=-1)` 折叠成负的 `NNum`，让含负元素的
整数矩阵也走 Bareiss；这是验证层的下一轮改进项。

## 6. 这一层实际抓到的 bug

1. **`80.8^{3}`**：LaTeX 写成 `\frac{8" + rs + "^{3}`，`8` 和 `0.8` 直接相连，
   读出来是 80.8³ 而不是 8·0.8³（纯文本那侧有 `·`，所以只有 LaTeX 错）。
   同款还有 `2" + asv` → `21.4`。修成 `8\cdot 0.8^{3}\cdot`。
2. **取模精度**：`79^{44} mod 89` 用 double 算成 0（1e83 超出精度），
   必须走 `BigInteger.ModPow`。
3. **几何级数外推**：比值 64/65 的级数用 1/N 外推会得到 65.078（真值 65），
   把级数截断档位加到 8192 后直接收敛。
4. **三重 Gaussian**：双重指数三层嵌套要 1.4e10 次求值，
   改有理映射 + GL 后 0.9 s、误差 1e-12。
5. **误差界虚高导致假通过**：误差界 6e8 时 `4×E` 变成天文数字，
   一个算歪的式子会被判"通过"；现在误差界过大一律判"未验证"。
6. **L5 融合层 Σ 吞因子**：`8ΣΣΣ1/3^{m+j+k}·(核心)` 中，`Σ` 的 body 把后面的
   核心乘进去了，两边都算成 288.888…（不是 325）。修复：`L5Hybridize` 给每个
   融合因子套不可见 `{}`；嵌套上下限用 `X.Paren` 包住。
7. **嵌套上限里的双积分**：`\int_0^1\int_0^3 1dr ds` 作为另一个积分的上下限时，
   C# 解析器会报"积分缺少微分"；给内层积分套 `\left(...\right)` 后正常。
   `L5BoundValue` 的 kind=1 已固定加括号。

## 7. ODE 是怎么做到的（`\frac{d}{dx}` 算子）

一条 LaTeX 里写不下"初值条件 + 解"，所以 ODE 不走 RK45，而是走**微积分基本定理**：

```
y 满足 y' = f(x, y)  ⟺  ∫_a^b y' dx = y(b) − y(a)
```

生成器把 `y'` 直接写成导数算子，并且**自归一化**（两边都写成积分，不出现刻意凑的系数）：

```
\int_0^1 (d/dx)(x e^x) dx
──────────────────────────  = 1        y = x e^x, y' = (1+x) e^x
\int_0^1 (1+x) e^x dx

\int_0^1 (d/dx)(e^{x²}) dx
──────────────────────────  = 1        y = e^{x²}, y' = 2x e^{x²}
\int_0^1 2x e^{x²} dx
```

分子靠**数值求导**得到，分母是普通的积分；两者都等于 y(1) − y(0)，比值为 1。
早先那种 `(1/e)·∫…` 的写法被评审指出"系数太刻意"，已换成这个形式。

关键点：**两套校验器都必须真的求导**，不能把生成器算好的值搬过来。
- C# `NDeriv`：5 点中心差分，步长按量级取 `1e-4·max(1,|x|)`；
- Python `Deriv`：同一套公式的独立实现。

踩过的坑：最初把 `free_vars(d/dx f) = free_vars(f) − {x}` 写错了——导数在 x 处取值，
当然依赖 x；写错会让积分把整个导数项当成常数，直接报"变量未绑定"。

## 8. 没有验证的东西（诚实清单）

- **误差界本身**：`E` 是估计值不是严格上界（没有用区间算术），
  所以"通过"的严格含义是"两套独立实现都算到 1e-6 以内"，而不是形式化证明。
- **真正的初值问题求解**：上面用的是 FTC 等价形式，不是 RK45。
  要做"任意 y'=f(x,y), y(0)=a"的独立求解，得先定义记号再在两套校验器里各写一个 RK45。
- **L5 v2 没有 SymPy**：构造层用精确整数/有理数，审计层用 FormulaAudit +
  Python numengine；这是“两套实现都算对”，不是 CAS 的形式化化简证明。
- **L5 v2 的 T3 是结构代理**：3-gram SimHash 不是语义 embedding；
  它识别“换数字不换结构”，不识别真正换一种表述的同构模板。
- **L5 v2 的 T1/T2/T4 是精确规则，T5 是构造时记录的模块边，T6 是编辑距离**；
  这些指标没有被外部标准校准，属于工程代理。融合版 T1 不再为 0（0.1521），
  因为旧 =1 模块被故意保留。
- **L5 只审计选中候选**：未选中的候选是 `audit_ok=false / audit_mode=skipped`；
  Python 只对最终 200 条逐条复算，不对所有候选复算。
- **L5 融合层是值保持包装**：嵌套积分壳、`(core)^{det=1}`、旧 =1 模块
  都不改变 325；CAS 可以先化简这些包装，再看到自然模型核心。
- **L5 v2 的批内轮换**：`BuildL5(seed)` 是 canonical 唯一映射；
  `--dump-random` / `--l5-*` 传 `preferredModel` 以满足近 10 道题不重复。
  同一 seed 在批内可能选另一个合法模型；审计链 `selection_mode` 会标注。
- **人工 rubric**：`docs/l5-v2-report.md` 里的分数是代理自评，没有独立评审。

## 9. 视觉与"不做的事"

- **折行功能已删除**（2026-10-21 晚）：长式子一律单行，靠 `MathBox` 的滚轮/按钮缩放查看。
  自检里有一张 WpfMath 支持矩阵（`--math-test`），17 条探针全部"实际 == 预期"，
  外加 `ZOOM_OK=1`（1 → 1.25 → 1.563 → 1.25 → 1）。
- **旧的最外层行列式外壳仍移除**（用户 2026-10-21 要求）：不再把整条链套进
  `\det\begin{pmatrix}<链>&0\\0&1\end{pmatrix}`。L5 融合版新增的是
  `(core)^{det(M)=1}`（行列式作为乘方），不是矩阵外壳。
  审计器的表达式矩阵元能力保留（整数矩阵仍走 Bareiss 精确路径，含表达式的走
  逐元求值 + 部分主元高斯消元）。
